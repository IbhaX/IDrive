# Contributor notes (AGENTS.md)

## Commands

| Task | Command |
| --- | --- |
| Install (runtime + dev) | `pip install -r requirements-dev.txt` |
| Run dev server | `idrive` (after `pip install -e .`) or `uvicorn app.main:app --reload` (or `make dev`) |
| Tests | `python -m pytest -q` (or `make test`) |
| Smoke check | `python tools/smoke.py` (or `make smoke`) |
| Re-extract content | `node tools/extract_data.mjs` (or `make extract`) |
| Lint/compile check | `python -m compileall -q app tests tools` |
| Visual check | `python tools/visual_check.py --base http://localhost:5000` (needs Playwright + Chromium) |

Python 3.12+, Node 18+ (extraction only). Windows-friendly: no shell-isms outside the Makefile.

## Conventions that matter

- **Typing is mandatory.** Every function has parameter and return types; collections are parameterised (`dict[str, Any]`), `Optional[T]` is explicit. Run the AST audit in `tests` context or `mypy`-style review before committing.
- **Layers:** `api/` (HTTP) → `services/` (application) → `models`/data stores. Routes never hold business logic; services never see `Request`/`Response`.
- **`app/data/*.json` is generated** by `tools/extract_data.mjs` — never hand-edit (except `ui_extra.json`, which is intentionally static and merged into the UI table server-side). After editing `Sadak Saathi.html`, run `make extract`; `meta.json` content version changes → clients refresh.
- **Frontend is vanilla JS modules, no build step.** Views render markup that mirrors the source app's classes (`panel`, `opts`, `signopts`, `rv`, `crow`, `mrow`, …) — do not rename classes without checking `app.css`. All UI strings come from `Data.UI` (ui.json + ui_extra.json) — no hard-coded copy in JS.
- **GSAP is vendored** in `static/vendor/gsap/`. Views call `Motion.*` helpers only; every animation must have a `prefers-reduced-motion` fallback and animate transforms/opacity only.
- **The exam answer key never leaves the server.** Mock papers are stored in `exam_papers`; the client gets stripped questions (`exams.strip_answers`). Keep it that way.
- **Progress merge rules** (client, `auth.js`): `seen` union; `box`/`wrong` per-key max; `best`/`played`/`mock` field-wise max; `tq` per-topic max; `lang` local wins. `PUT` carries the base version; 409 → re-merge + retry once.
- **Curriculum content** lives in `app/data/curriculum/` and *is* hand-edited (unlike the generated `app/data/*.json`). After editing, run `python -m pytest -q tests/test_curriculum.py` — the linter must stay clean. Legal statements need a `law` note **and** a reference id with a `verified` date; never add money amounts.
- **Sign details** (rich text under each sign in the sign sheet: `more`, `where[]`, `when[{s,d}]`, `mistake`) live in `app/data/curriculum/sign_details.json` keyed by sign id, Malayalam mirror in `ml/sign_details.json`; served at `/api/library/signs` (in the offline manifest) and rendered by `learn.js` `L.detailHtml`. No legal claims or money amounts.
- **Speed limits** (`#limits`, `speed.js`): `app/data/curriculum/speed_limits.json` — per region (`kerala`, `india`) a list of roads and vehicles with `lim[]` (one per road, `null` = not allowed), labels as inline `[en, ml]`, and `refs` into `references.json` (Kerala G.O.(P) 15/2023 as amended by 9/2024; MoRTH S.O. 1522(E) 2018). The linter checks shapes and refs. When a notification changes, update the numbers and the reference's `verified` date.
- **Malayalam curriculum** lives in `app/data/curriculum/ml/<module id>.json` (+ `library.json` for lights, parts, scenarios) and mirrors the English structure field by field. The API zips them into `[en, ml]` pairs; views render any content value with `I18n.X` (HTML) or `I18n.one` (plain text for attributes/crumbs). When you add or change English text, update the Malayalam mirror — `test_malayalam_translation_is_complete` fails otherwise.
- **Views and routes:** a route is a `view/param/param2` string. Every route has a real address (`/learn/mand`, `/sign/stop`, `/lesson/<id>`, `/theory/<topic>`, `/glossary/<slug>` → `theory/gloss/<slug>`, `/about|privacy|terms|install` → `page/<name>`); `app.js` `curRoute()` reads it from the path (or from an old-style `#view/a` hash, which is rewritten to the path), `go()` pushes history, `setHash()` replaces it, `popstate` handles Back. Links inside views keep using `href="#view/…"`; plain `href="/…"` links are intercepted too. `?lang=ml` sets the language and is kept in URLs while Malayalam is on. Add a view by registering it in `VIEWS` (and `TABS` if it needs a tab) **and** a page for it in `app/web/seo.py` `resolve()` (plus a sitemap entry in `SITEMAPS` if it is indexable). New UI copy goes into `ui_extra.json` as `[en, ml]`.
- **Server-rendered pages (SEO/AEO):** `app/web/seo.py` renders every URL into the shell's `<main id="app">` with a unique title/description, canonical, `hreflang` en/ml/x-default (`?lang=ml`), og/twitter tags and JSON-LD (FAQPage text must equal the visible `<p class="answer">`, BreadcrumbList, LearningResource/Article/Course, Organization/WebSite/WebApplication on `/`). Every page opens with an answer-first paragraph. Unknown paths/ids are real 404s with `noindex`; `/ask` and `/progress` are `noindex`. The catch-all route is last in `main.py`; unmatched `/api/*` still returns JSON 404. Crawler files: `/robots.txt` (search/answer bots allowed, training bots disallowed, `Content-Signal ai-train=no`), `/sitemap.xml` index → `/sitemaps/<section>.xml` (lastmod = source file mtime), `/llms.txt`, `/llms-full.txt`. `/shell` is the bare shell the service worker caches for offline navigation. About/Privacy/Terms/Install prose lives in `app/web/trust.py` — **update the privacy text whenever data handling changes**. `tests/test_seo.py` renders every sitemap URL in both languages.
- **Settings for the public site:** `SITE_URL`, `CONTACT_EMAIL`, `PLAY_STORE_URL` (Install page, footer, JSON-LD `sameAs`), `GA_MEASUREMENT_ID` / `ADS_ID` / `ADS_SIGNUP_LABEL` (optional; empty = no analytics script and no Google hosts in the CSP), `FORCE_HTTPS` (off; prefer Cloudflare "Always Use HTTPS"), `REDIRECT_WWW` (on). Security headers: HSTS only when the request came over https (`X-Forwarded-Proto`), `X-Frame-Options: DENY` + `frame-ancestors 'none'`, Permissions-Policy.
- **Analytics (optional):** `analytics.js` is inert unless the `ga-id`/`ads-id` meta is present; then it loads gtag.js, sends one `page_view` per route and events `sign_up`, `mock_test_start`, `mock_test_complete`, `quiz_complete`, `lesson_complete`, `pwa_install`, and keeps first/last-touch `gclid`/`gbraid`/`wbraid`/UTM in `localStorage idrive-attr`, sent with register / Google sign-in and stored (whitelisted keys only) in `signup_attribution`. **Account deletion:** `DELETE /api/auth/me` (Progress page, hold-to-confirm) deletes user, sessions, progress and attribution, and detaches exam papers/attempts.
- **Animation scope:** call `Motion.scoped(fn)` for any timeline/ScrollTrigger a view creates; `render()` calls `Motion.resetView()` so nothing leaks between routes. Scroll reveals use the `.rvl` class (`.rv` belongs to the exam review list).
- **Progress blob additions** (`les`, `bm`, `rec`, `days`, `rq`, `hz`, `lab`, `secs`) merge as: `les` field-wise max; `bm` latest `|ts|` wins (sign = on/off); `days` union; `hz`/`rq` per-key max; `lab.rt` min; `rec` local order first; `secs` max.
- **Content safety:** no fine amounts in data; stories carry the illustrative label (a data field); the RTO/Parivahan disclaimer stays in the footer + articles. Track unverified facts in `content_review.md`.

- **Offline:** after the service worker activates it fetches `/api/offline/manifest` (`services/offline.py`: every sign, theory article, lesson, library list, the search index) into `idrive-data-v1`, reports progress to pages (`offline-progress` / `offline-ready` messages → footer line `#offlineStat` via `pwa.js`), and rebuilds the pack when the saved build differs from the page's. Account-only features (mock tests, practice, sign quiz, progress sync, AI answers) are never cached; offline they show `testsOffline`, the instructor falls back to on-device search (`Search.local`, same scoring as the server over `/api/curriculum/search-index`), and progress stays local and syncs on `online`. `Auth.restore` only signs out on a real 401 — offline it keeps the last user (`idrive-user`). When adding a new read-only endpoint the app needs, add it to the manifest.
- **PWA:** `app/static/sw.js` is served at `/sw.js` with `__BUILD__` replaced by the build fingerprint (new worker per deploy). Shell = network first, `/static/*` = cache first (URLs are content-versioned), read-only content APIs = network first with offline fallback; auth/progress/exam/instructor are never cached. Install UI lives in `pwa.js` (native prompt on Chrome/Edge/Android, Share-sheet steps on iOS, File › Add to Dock on macOS Safari). Icons: `app/static/img/`, manifest: `app/static/manifest.webmanifest`.
- **Splash:** `#splash` in `index.html` (inline script: once per browser session, 8 s failsafe); `app.js` `hideSplash()` lifts it after the first route renders, after the ~1.55 s intro plus a 3 s hold. CSS keyframes under "startup splash"; reduced motion gets a short fade.
- **3D car:** `car3d.js` loads three.js r170 from jsDelivr through the import map in `index.html` (original addons; the map is allowed by a CSP sha256 hash computed in `pages.importmap_hashes`) and the Khronos "Car Concept" glTF — the **WebP variant** (plain geometry + WebP images, ~10 MB raw, gzip-compressed by the server), because the KTX2+Draco variant's decoder workers hung on phones; pinned commit — only when the student opts in; the choice is remembered (`idrive-3d`) and the service worker caches both (`idrive-3d-v2`). The CSP allows jsDelivr for scripts; no WebAssembly or blob: workers are needed. Orientation/axles are detected from the model's materials (Headlight, Tire*); tyres/brakes highlight real meshes, inner parts are built from three.js primitives in `build()` (one Group per part in a local x-forward/y-up/z-right frame, metres for a 4.4 m car, real-looking materials; the system colour is only the emissive selection glow) and shown in X-ray. `node`-run the builder against a recording mock of three.js before pushing changes to it (see the commit that introduced the detailed parts). The model is served same-origin from `/models/<MODEL_KEY>/*` (key = variant + pinned commit; files are immutable, so a new model version must get a new key) (`services/model_mirror.py` downloads it into `data/models/carconcept-webp/` in the background at startup — size-checked, `MIRROR_3D=false` disables it, tests set that — and a file not yet copied is fetched by the server on demand — students never talk to GitHub; `/api/models/carconcept/status` lists anything missing), because raw.githubusercontent.com is slow or blocked on some Indian ISPs. Attribution (CC BY 4.0) is shown under the viewer; Khronos logo meshes are hidden. The viewer element is persistent — re-rendering the explorer re-attaches it, never reloads it. No inline scripts: the CSP forbids them (the splash logic is `splash.js`).
- **Logo:** the top-bar mark is the animated road-"i" (SMIL, so it runs on iOS); `app.js` pauses it under reduced motion. Static versions: `img/logo-mark.svg`, `img/icon.svg`, `img/favicon.svg`; animated: `img/logo-animated.svg`.

## Where things live

- Question engine port (`signQ`/`prep`/`buildMock`/`buildPractice`/`build_sign_quiz`): `app/services/exams.py`
- Progress blob service + versioned 409: `app/services/progress.py`
- Sessions (hashed tokens, expiry sweep at startup): `app/services/auth.py`
- Frontend event contract (`data-open`, `data-cat`, `data-etopic`, `data-ans`, `data-act`): `app/static/js/app.js` — mirrors the source app's delegation switch.
- Curriculum store, validation, search: `app/services/curriculum.py`; instructor retrieval + provider call: `app/services/instructor.py`
- New frontend modules: `course.js` (home, curriculum, lesson reader, knowledge checks, revision), `labs.js` (stopping, reaction, engine + lab router), `labs2.js` (following distance + gap drill, cornering friction circle, crash energy, headlight reach, mirrors & blind spots; controls use `data-act="lab.<name>"`), `labs3.js` (20 labs on a small declarative engine: `def(id, {st, ctl, calc, draw, run?, live?, place?})`; strings `lab_<id>`, `labSub_<id>`, `m_<id>` + per-lab keys; groups and order in `labs.js` `Lb.GROUPS`), `labs4.js` (20 more labs on the same engine via `Labs.L3` — check `ui_extra.json` for key clashes before adding per-lab strings), `vehicle.js`, `hazard.js` (52 scenarios in `scenarios.json`; each has `cat` — ped, two, junc, hwy, heavy, rural, wx, town — for the index filter, optional `mood` night/rain/fog overlay, actor kinds incl. auto, cycle, ball; ego car sits at (150,500) facing up, our lane x≈150, oncoming x≈250 with `rot:180`; Malayalam in `ml/library.json` `scenarios`), `instructor.js`, `search.js`
- Bilingual helpers (`T`, `TP`, `BP`, `BPP`, `cn`, `topN`, `topDot`): `app/static/js/i18n.js`

## Testing notes

- `tests/conftest.py` builds each test a fresh SQLite file via `database_url` env var and clears the settings cache — keep env-dependent fixtures behind that pattern.
- Mock-score tests read the stored answer key from `exam_papers.payload` directly (`tests/helpers.py`) — real clients cannot do this; it exists only to verify scoring.
- `tests/test_data.py` is the extraction-drift guard: it fails if counts/fields deviate from the source (255/9/18/18/471/83).
